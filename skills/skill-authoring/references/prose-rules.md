# Prose rules

- When in doubt, delete. Keep a sentence only if it changes what the host does.
- Say what to do. Give the reason only when the rule is confusing without one.
- Write a rule in one line when it fits. Move examples and long explanations to references.
- Use the imperative, with the host as the implied subject: "Read the file", not "The agent should read the file".
- Give each thing one name across all files. Steps, roles, and files keep the names SKILL.md gives them.
- Don't restate what a file in the folder already says, such as a template, schema, or script. Point at it.
- Don't restate another skill. Call it by name.
- When a rule appears a second time, or the user keeps making the same correction, turn it into a script or a validator check instead of more prose.
- Give numbers, not adjectives: "at most 3 bullets", not "keep it short".
- Don't use capital letters, "IMPORTANT", or warnings to make a rule stick. If a rule gets ignored, move it earlier, make it a step, or enforce it with a script.
- Cut "make sure to", "it is important that", "you should", and "please".
